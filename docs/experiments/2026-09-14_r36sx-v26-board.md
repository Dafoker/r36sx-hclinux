# Interpretation

1. El pipeline demostró que puede reconstruir el hardware description stock con fidelidad total: nuestro DTB compilado es semántica Y binariamente igual al stock recompilado (0 allowlist).
2. La diferencia de entry/data-size vs el kernel stock de fábrica proviene del config del fabricante (no incluido en SDK) — documentada; NO es del DTS (DTB idéntico).
3. La consola bootea desde SD (NOR 3 particiones) → Fase 5 (cuando se autorice) será reemplazo de archivos en SD, sin tocar NOR/bootloader/AVP.
4. Upstream-clean garantizado: board propia separada; d3100_v20 intacto (diff 0 archivos vendor).

# Decision

- ADR-010 (en DECISIONS.md): r36sx-v26 = board stock-equivalent con DTS verbatim + macros; cualquier cambio futuro al DTS requiere allowlist + ADR.
- Fase 4 CERRADA con artefactos HOST/BUILD validados. **NO desplegar** — Fase 5 (SAFE PHYSICAL BOOT TEST) requiere autorización explícita del usuario y protocolo de rollback.
